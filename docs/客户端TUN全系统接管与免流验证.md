# 客户端 TUN 全系统接管 · 大流量下载强制隧道 · 免流权威验证指南

> 面向智能体(Agent)的操作提示词。本文件是 `部署提示词.md` 的**客户端侧进阶篇**：讲清楚如何让**整个系统 / 具体应用**稳定走 IPv6 隧道免流，以及**如何正确验证"某个下载是否真免流了"**——这是最容易踩坑的地方。

## 0. 适用场景

服务端 Worker/订阅已按 `部署提示词.md` 部署好、Clash（Verge Rev / mihomo）能代理外网之后，用户往往有这些诉求：

1. **让所有桌面端应用都走免流**（不只是浏览器）——需要开 **TUN 模式** + 配好分流，让系统路由全接管。
2. **让某款大流量应用**（典型：游戏下载器，如 Steam 的 `*.steamcontent.com`）**稳定走隧道**，而不是偶尔被 GEOIP 判成国内直连计费。
3. **严格验证**某个应用到底走没走 IPv6 隧道、有没有偷着走 IPv4 直连计费。

> 核心前提不变：**只有校园网 IPv6 环境免流**；换手机热点(纯 IPv4)会失效并计费。

---

## 1. 两个"走代理"的入口：系统代理 vs TUN（必须分清）

Clash 接管流量有两条**本质上不同**的入口，**这是后面所有验证不踩坑的前提**：

| 入口 | 谁走它 | 流量路径 | TUN 网卡计数是否增加 |
|------|--------|----------|--------------------|
| **系统代理(HTTP/SOCKS, 如 `127.0.0.1:7897`)** | 认系统代理的应用（浏览器、多数下载器） | 应用 → `127.0.0.1:代理端口` → mihomo 匹配规则 → 隧道出口 | **不经过 TUN 网卡 → 不增加** |
| **TUN(虚拟网卡, 如 Meta)** | 不认代理/或被 TUN 劫持的应用 | 应用 → TUN 网卡 → mihomo → 隧道出口 | **增加** |

**⚠️ 后果（重要）**：一个走**系统代理**的应用，哪怕它 100MB 全走隧道，**TUN 网卡的收/发字节也几乎不动**。所以——

> **绝不能用"TUN(虚拟)网卡字节是否增长"来判断某个应用有没有走隧道。** 否则会得出"明明在免流、却判成没走隧道"的错误结论。

## 2. 让"整个桌面系统"走免流：TUN 模式 + 内网分流

- Clash Verge → 打开 **TUN 模式**开关（在界面上手动开/关；避免直接改配置以防内核不重载）。
- TUN 打开后默认路由被接管（虚拟网卡 `0.0.0.0/0` 与 `::/0`，metric 最高），**系统内所有应用**的流量都会进 Clash路由。
- **必须在分流规则里保留国内直连**，否则内网/国内网站会被绕行隧道、又慢又可能计费：

```yaml
rules:
  # ① 境外重点域名/大流量下载 CDN 钉隧道（见 §3），要放在 ② 前面
  ...
  # ② 国内分流：先按域名集合，再按归属 IP，落 DIRECT
  - GEOSITE,CN,DIRECT
  - GEOIP,CN,DIRECT
  # ③ 兜底：其余一律走隧道
  - MATCH,🚀 免流
```

- **加分项**：GeoSite/GeoIP 数据文件会被 mihomo 自动载入（验证时留意 `GEOSITE,CN` 已加载条数>0）。

## 3. 大流量下载应用（如 Steam）务必【显式钉隧道】

### 现象 / 根因

`*.steamcontent.com`（Steam 下载 CDN）这类域名，如果只靠 `GEOIP,CN,DIRECT` 兜底分流，**当该 CDN 解析到中国大陆 IP 时会被判成 `GEOIP,CN → DIRECT` → 走物理网卡 IPv4 直连 → 计费**。只有解析到境外 IP 时才"碰巧"走隧道，极不稳定。

### 药方：显式域名规则，放在 `GEOIP,CN` 之前

在 `# 国内分流` 之前插入（Steam 实测有效覆盖 `steamcontent / steampowered / steamstatic / steamcommunity` 等全部子域）：

```yaml
rules:
  - DOMAIN-SUFFIX,steamcontent.com,🚀 免流
  - DOMAIN-SUFFIX,steampowered.com,🚀 免流
  - DOMAIN-SUFFIX,steamstatic.com,🚀 免流
  - DOMAIN-SUFFIX,steamcommunity.com,🚀 免流
  - DOMAIN-SUFFIX,steamstatic.akamaized.net,🚀 免流
  # ……后续才是 GEOSITE,CN,DIRECT / GEOIP,CN,DIRECT
```

> 关键：**位置必须在 `GEOIP,CN` 之前**、并在 mihomo 里校验（`verge-mihomo -t -f <配置文件>`，报 `test is successful` 即通过）。

### 生效细节（Clash Verge / mihomo 常见坑）

- 修改生效的是**合并后的运行内核配置**（Clash Verge 里叫 `clash-verge.yaml`），**不是**只改订阅源 profile。
- Clash Verge 对本地 profile 不会监听文件变化**自动重载**——改完 profile 后，必须让它在**界面里对该 profile 重新载入/重新订阅**（或切走再切回），内核才会重新合并出新规则。
- 改完重载后，**用 sidecar 日志确认命中**——看到 `match DomainSuffix(...) using 🚀 免流` 这类日志，就能确认新规则已接管（对比兜底的 `match match`）。

## 4. 权威验证：应用是否【真】走 IPv6 隧道免流

下面是给智能体的**可复现判定流程**（本项目踩坑后沉淀，务必照着做，别自己发明）。

### ❌ 错误判据（不要用）

- **TUN/物理网卡字节差分**：会误判（见 §1，系统代理入口流量不进 TUN 网卡）。
- **只报 hit mihomo 命中某条规则**：命中"隧道规则" ≠ 字节真的进了隧道并免流。

### ✅ 正确判据：netstat 采样 + mihomo 日志【端口级闭环】

**核心思想**：下载进行时，抓应用建立的每条 TCP 连接，看它们**只指向本机代理端口**（无公网 IP 直连），并且**同一批端口在 mihomo 日志里命中隧道规则**——两层的端口一一对应即铁证。

**步骤：**

1. **确认应用 PID**：
   ```powershell
   Get-Process <应用名> | Select Id,ProcessName
   ```

2. **下载进行时，持续采样**该进程 `ESTABLISHED` 连接（写脚本轮询 netstat，取本地端口→远端IP:端口）：
   ```bash
   netstat -ano | grep -E "ESTABLISHED" | grep " <PID> "
   ```
   若采样期间该进程出现过**任何非 `127.0.0.1`、非内网段(192.168/10./172.16)的公网 IP:443 → 就是直连计费**。

3. **对照 mihomo sidecar 日志**同一时刻的连接（日志含 `源:本地端口 -> 远端域名:443` 与命中规则）：
   ```
   127.0.0.1:57509 --> cacheXX.xxx.com:443  match DomainSuffix(steamcontent.com) using 🚀 免流
   ```

4. **闭环判定**：netstat 里看到的**本地端口号**，与 mihomo 日志**同一端口**、且目标域名一致、且命中你预期的域名规则 → 证明该连接是 `应用 → 127.0.0.1:代理 -> mihomo匹配规则 → 隧道出口`，**没有任何一个公网 IP 直连** → **免流成立**。

5. （加分）全窗口 `侧栏日志无 TLS/握手/超时错误`，且规则命中是从兜底 `Match` 变成了 `DomainSuffix(具体域名)`——说明你的显式钉隧道规则真正接管。

## 5. 手机版订阅需同步分流

- 桌面与**手机端分开两份 profile**，规则的**分流段要一致**（同样的国内直连 + 大流量下载域名钉隧道），只是代理端点不同。
- 手机端**必须开客户端 IPv6 开关**（见 `部署提示词.md` §10 坑 6），否则纯 IPv6 节点全部超时。

## 6. 验收清单

- [ ] TUN 开启后系统默认路由被虚拟网卡接管(`route print` 见 `0.0.0.0/0` 最高优先级)
- [ ] 国内站仍直连(内网/百度秒开)；外网走隧道(`curl -I https://www.google.com`)
- [ ] 大流量下载应用被 `DOMAIN-SUFFIX` 钉住(侧日志命中 `DomainSuffix`，且位于 `GEOIP,CN` 之前)
- [ ] 下载场景权威验证：netstat 采样全 `127.0.0.1:代理` + 与 mihomo 日志端口一一对应命中隧道 → 无公网直连
